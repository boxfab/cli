# Upstream

The BoxFab CLI is derived from the open-source
[E2B CLI](https://github.com/e2b-dev/E2B/tree/main/packages/cli) (MIT) and includes
modifications for BoxFab's sandbox infrastructure. BoxFab is an independent project and is not
affiliated with or endorsed by E2B.

## Pinned source

- Repository: https://github.com/e2b-dev/E2B
- Path: `packages/cli`
- Release: `@e2b/cli` 2.23.0 (tag `@e2b/cli@2.23.0`)
- Commit: `a91e33a3014a7644a2d39e03501d25b21ad727c0`
- Bundled SDK: `e2b` 2.61.0 from npm, pinned exactly (the SDK version that CLI release was cut
  against; upstream builds it from the monorepo source).

## How the code is produced

`src/`, `tests/`, `tsconfig.json`, `tsdown.config.ts`, `vitest.config.ts`, `LICENSE-E2B` and
`CHANGELOG-E2B.md` are generated by `scripts/sync_upstream.py` from the pinned commit and are
never edited by hand. The script copies the upstream package, removes the files listed below,
copies `overlay/` on top, and applies a fixed set of rewrites, each asserting how often it
matched. A final check fails the sync if any E2B domain, config path or command name is left in
`src/`.

| Change | Why |
|---|---|
| `src/boxfab-env.ts` (overlay), imported first: removes every inherited `E2B_*` variable and maps `BOXFAB_*` onto the names the code and the bundled SDK read; `BOXFAB_DOMAIN` defaults to `boxfab.io` | a BoxFab install never picks up an E2B key or domain, nor sends a key to E2B's service |
| `src/user.ts` (overlay): config in `~/.boxfab/config.json` holding the API key only | BoxFab has no OAuth sign-in for CLIs |
| `src/commands/auth/*` (overlay): `login` takes an API key (prompt or `--api-key`) and checks it against the API; `logout`, `info`; `configure` removed; `src/utils/token-refresh.ts` removed | same |
| Dashboard link `${DASHBOARD_BASE}/sandboxes/<id>`, base `https://dashboard.boxfab.io` | the BoxFab dashboard's sandbox page |
| Docs links `https://boxfab.dev/docs` | |
| Program name, help texts and messages: `e2b` → `boxfab`, product name in prose → BoxFab, `BOXFAB_API_KEY` in messages | user-facing name |
| Internal identifiers that show up in error output (`E2BRequestError` and the like) → `BoxFab*` | they appear in error names and stack traces |
| User-Agent integration `e2b-cli/<ver>` → `boxfab-cli/<ver>` | |
| `template init`: generated Python imports `boxfab`; `e2b:build:*` targets → `boxfab:build:*`; README template (overlay) | generated projects target BoxFab |
| Monorepo paths (`../js-sdk/src`, `../dockerfile-utils-js`) removed from tsconfig, vitest and tsdown configs; `pnpm build` → `npm run build` | standalone repository using the published packages |
| `init.ts` catch value narrowed with `String(err)`; generated-code test fixtures excluded from type-checking | the published SDK's type declarations are stricter than its source |
| Tests: same rewrites; `BOXFAB_*` variables; domain default `boxfab.io`; `tests/boxfab-env.setup.ts` (overlay) applies the mapping in every test worker and refuses to run against an E2B domain | tests exercise BoxFab only |

`scripts/postbuild.mjs` rewrites two user-visible messages inside the bundled SDK (the
missing-API-key message and one template-build error), each asserted to match exactly once.

Deliberately unchanged:

- The bundled `e2b` JS SDK itself, the wire protocol, the `e2b_` API-key prefix, envd and API
  client code: they are protocol, not branding.
- Legacy file names read by `template migrate` (`e2b.toml`, `e2b.Dockerfile`): they are E2B's
  formats being migrated from.
- TypeScript output of `template init` imports the `e2b` package (there is no BoxFab JS SDK); its
  README tells users to set `E2B_DOMAIN=boxfab.io`.
- Code comments and internal identifiers that never reach the user.

## Verification (2026-11-02)

- Upstream test suite: 142/142 passing, including the live tests against `boxfab.io` (sandbox
  create/connect/exec/stdin piping/pause/resume, template create and list) with a tester key.
- Installed from the packed tarball into a clean prefix with an empty `HOME`: help and version,
  `auth login` with a valid and an invalid key, `auth info`, `sandbox create -d`/`list`/`exec`
  (`hostname` → `boxfab`, Jupyter health OK)/`info`/`kill`, `template list`, `template init`
  (Python). With `E2B_API_KEY` and `E2B_DOMAIN=e2b.app` set in the shell, the CLI ignored them.
- Bundle and source map contain no local paths or internal host names.

Known: the BoxFab API server's own message for an invalid key still links to E2B's documentation
("Invalid API key, please visit https://docs.e2b.dev/api-key …"). That text comes from the
server, not the CLI; it is fixed in the deployment's API patch set.

## Updating to a newer upstream release

1. Set `UPSTREAM_TAG` / `UPSTREAM_COMMIT` in `scripts/sync_upstream.py`, and the `e2b` version in
   `package.json` to the SDK release that CLI version was published with.
2. `python3 scripts/sync_upstream.py`; fix any rule whose count no longer matches.
3. `npm ci && npm run build && BOXFAB_API_KEY=… npx vitest run`.
4. Update this file and `CHANGELOG.md`.
